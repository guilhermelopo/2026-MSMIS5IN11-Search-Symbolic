Les deux ensemble, en alternance. Un mot sur la méthode de travail, parce qu'elle explique la qualité du reste. La répartition est en tranches verticales, pas en couches : chacun possède une moitié du pipeline de bout en bout — Guilherme la représentation et les objectifs, Lucas la recherche et l'évaluation — mène une des deux expériences principales, et relit la couche de l'autre. Personne n'a écrit du code que l'autre n'a pas lu. L'historique Git compte treize commits, petits, un changement par message : les deux bugs que nous venons de montrer y figurent chacun avec le commit du test qui les ferme, donc la correction est vérifiable, pas seulement racontée. Quatre README, un par couche, et surtout : les justifications sont dans les docstrings, au plus près du code qu'elles expliquent. Sur les risques, nous en avons rencontré trois. RDKit refuse de se charger sur nos machines Windows, nous avons donc basculé toute l'exécution sur Colab. Le réseau de la salle est incertain, donc toutes les figures et toutes les mesures sont versionnées. Et la métrique peut déraper sans qu'on le voie, d'où le vérificateur indépendant. Dernier point, écrit en bas de la diapositive : le squelette du code et le README ont été écrits avec l'aide d'un agent de code, et nous le déclarons, comme la charte du dépôt l'exige. Les mesures, le notebook et ces diapositives sont à nous.
